# Правила проекту BRAVO SYSTEM REPORT

## Мова і стиль

- Усі відповіді — українською.
- Усі Git commit messages — українською.
- Усі описи PR, merge та змін — українською.
- Консольні повідомлення, логи та документація — українською.
- У PowerShell-скриптах не використовувати emoji.
- Консольний вивід: секції `=== ... ===`, маркери `[INFO]`, `[OK]`, `[SUCCESS]`, `[ERROR]`.
- Кольори PowerShell дозволені, але текстовий contract output не повинен залежати від кольорів.

## Обов'язковий формат локальних PowerShell-команд

```powershell
Clear-Host
Set-Location "E:\GitHub\BRAVO_SYSTEM_REPORT"
$ErrorActionPreference = "Stop"
```

## Правило `ок / готово / зроблено / перевіряй`

Такі повідомлення означають: перевірити поточний етап без зайвих уточнень, проаналізувати локальний log або GitHub PR, перевірити diff, head SHA, mergeability і checks, після чого дати точний fix або наступний крок.

## Git workflow

1. Синхронізувати `main` з `origin/main`.
2. Створити patch-гілку від `main`.
3. Внести зміни.
4. Запустити `git diff --check`.
5. Зробити commit українською.
6. Запушити patch-гілку.
7. Створити PR українською.
8. Перевірити PR diff і GitHub Actions.
9. Merge виконувати лише після зелених checks.
10. Після merge синхронізувати локальний `main`.
