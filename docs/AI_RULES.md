# Правила роботи з AI у проекті BRAVO SYSTEM REPORT

Цей документ визначає правила використання AI-асистентів (Claude, Copilot та інших)
під час розробки проекту. Він доповнює `docs/PROJECT_RULES.md` і не скасовує його.
У разі конфлікту пріоритет має `PROJECT_RULES.md`.

## 1. Мова та комунікація

- Усі запити до AI, відповіді AI, commit messages, PR descriptions і документація — українською.
- AI-згенеровані консольні повідомлення дотримуються маркерів `[INFO]`, `[OK]`, `[SUCCESS]`, `[ERROR]`.
- Emoji заборонені всюди, крім HTML-звіту.

## 2. Джерело істини

- AI працює тільки з модулями у `src/`.
- `dist/Get-BravoSystemReport.ps1` — build-артефакт. AI не редагує його вручну і не пропонує правки до нього.
- Кореневий `Get-BravoSystemReport.ps1` — wrapper; змінюється лише за окремим рішенням команди.
- Будь-яка зміна runtime-логіки завершується локальним запуском `Build-BRAVO-SystemReport.ps1`,
  який перегенеровує `dist` і `sha512`. AI має нагадувати про цей крок, якщо не може виконати його сам.

## 3. Архітектура та нумерація модулів

- Нові collector-и отримують наступний вільний номер у діапазоні `30–39`
  (наступний вільний перевіряється по факту в `src/`, а не по пам'яті AI).
- Нові export-и — діапазон `50–59`. Health-логіка — `40-Health.ps1`. Основний flow — `90-Main.ps1`.
- Кожен новий модуль обов'язково додається у `src/BRAVO.build.json` у правильній позиції.
- Порядок підключення модулів у `BRAVO.build.json` не змінюється без окремого обґрунтування.
- Перейменування чи перенумерація існуючих модулів — тільки за рішенням команди, не за ініціативою AI.

## 4. Кодові конвенції для AI-згенерованого PowerShell

- Цільова платформа: Windows PowerShell 5.1. Синтаксис PowerShell 7 (`??`, `?.`, ternary) заборонений.
- Кожен collector — функція `Get-Bravo<Область>Audit` з `[CmdletBinding()]` і `param()`.
- Дані записуються тільки у `$script:Report.<Секція>`; нові секції спочатку додаються
  у `src/20-ReportModel.ps1` з дефолтними значеннями.
- Помилки збору: `Add-AuditError -Section '<Секція>' -Message $_.Exception.Message` у `catch`.
  Порожні `catch`-блоки заборонені, крім свідомо ігнорованих сценаріїв з коментарем.
- Знахідки: `Add-AuditFinding -Severity 'CRITICAL|WARNING' -Category '<Категорія>' -Message '...' -Recommendation '...'`.
  Кожна знахідка має містити конкретну рекомендацію.
- Консольний вивід через змінні-іконки (`$IconOk`, `$IconError`, `$IconGear` тощо), не через літерали.
- WMI/CIM — тільки через `Get-AuditObject`; дати — через `Convert-AuditDateTime`.
- Повільні або мережево-залежні перевірки гейтуються профілями (`Deep`/`Forensic`)
  або окремим switch-параметром у `src/05-Params.ps1`.

## 5. Формат файлів

- `.ps1` — UTF-8 з BOM, CRLF (див. `.editorconfig`). AI зобов'язаний зберігати BOM і CRLF при редагуванні.
- `.md` — UTF-8 без BOM.
- AI не виконує масове переформатування файлів (line endings, trailing whitespace, відступи)
  разом зі змістовними змінами: форматування — окремим commit, якщо взагалі потрібне.

## 6. Контракти даних

- Зміна структури `$script:Report` — це зміна контракту JSON. Вона супроводжується:
  - оновленням `SchemaVersion` у `20-ReportModel.ps1` за правилами semver-подібного версіонування;
  - синхронним оновленням HTML/CSV-експортів, якщо нові дані мають бути видимими;
  - записом у `CHANGELOG.md`.
- Видалення або перейменування існуючих полів звіту — тільки за рішенням команди.
- Нові HTML-таблиці підключаються через `New-BravoTableToolbarHtml` і клас `data-table`,
  щоб пошук та лічильники працювали автоматично.

## 7. Перевірка AI-згенерованих змін

- AI-код проходить той самий шлях, що й людський: patch-гілка → PR → review → зелені checks → merge.
- Мінімальна локальна перевірка перед PR:
  1. `Build-BRAVO-SystemReport.ps1` без помилок;
  2. parser check для `dist` (`[System.Management.Automation.PSParser]::Tokenize` або запуск з `-WhatIf`-логікою);
  3. runtime test у профілі `Quick` з `CollectionErrors=0`;
  4. валідність JSON-звіту.
- Автор PR зобов'язаний прочитати і зрозуміти AI-згенерований diff повністю.
  «Згенеровано AI» не є обґрунтуванням у review.
- AI-згенеровані зміни, що торкаються security-логіки, elevation, мережевих запитів
  або збору персональних даних, проходять review щонайменше двох членів команди.

## 8. Безпека та конфіденційність

- У промпти AI заборонено передавати: реальні звіти з машин замовників, IP-адреси,
  серійні номери, імена користувачів, домени замовників, вміст журналів подій.
  Для прикладів використовуються синтетичні дані.
- AI не додає в код: збір паролів, токенів, private keys, cookies, browser credentials,
  жорстко закодовані публічні IPv4 (перевіряється у CI), зовнішні HTTP-запити без окремого рішення команди.
- Залежності: тільки вбудовані можливості Windows PowerShell 5.1 / стандартні COM/WMI/CIM API.
  Зовнішні модулі (PSWindowsUpdate тощо) не додаються — монолітність `dist` є вимогою.
- AI-згенерований код, що виконує запис у систему (registry, служби, файли поза OutputPath),
  заборонений: скрипт лишається read-only аудитом.

## 9. Що AI заборонено робити без явного запиту

- Редагувати `dist/`, `*.sha512`, git-історію, теги і релізи вручну (регенерація через `Build-BRAVO-SystemReport.ps1 -CreateSha512` — не "ручне редагування", а сanкціонований спосіб з п.2).
- Довільно змінювати `$ScriptVersion`, `SchemaVersion`, номери модулів, назви публічних функцій без зв'язку з поточним запитом.
  Виняток — обов'язковий бамп `SchemaVersion` за п.6, коли контракт `$script:Report` змінюється як **прямий наслідок** уже узгодженого із запитом користувача завдання (наприклад, додавання нового поля в рамках задачі, яку попросили зробити): це не "довільна" зміна версії, а вимога п.6, і її пропуск — сам по собі порушення правил.
- «Покращувати» код поза межами поставленої задачі (drive-by рефакторинг).
- Додавати нові параметри запуску, нові вкладки HTML або нові файли експорту.
- Видаляти або послаблювати існуючі перевірки, findings і пороги Health Score.

## 10. Фіксація AI-участі

- Якщо зміна повністю або переважно згенерована AI, це зазначається у описі PR
  одним рядком: `AI-assisted: <інструмент>`.
- Відповідальність за merge несе людина, що його виконала, незалежно від походження коду.
